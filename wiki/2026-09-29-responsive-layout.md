## 배경

1920·1366·1024·768·390px 창에서 점검한 결과:

- 재구성 보기 높이가 220px 고정이라 창 높이를 따라가지 않았고, 1366×768에서 위쪽 편집 패널이 좁았다.
- 860px 이하에서 상세 상단바의 검수 완료·내보내기가 잘렸고, 390px에서는 페이지 가로 스크롤(scrollWidth 411)이 생겼다. 원인은 상단바와 재구성 도구 모음(Markdown 버튼) 두 곳이었다.
- 편집 패널 상단 줄에서 "자동 저장"이 두 줄로 깨졌다.
- 세로로 쌓이는 화면(≤860px)에서 오른쪽 패널 높이 제한이 없어 비교 탭이 약 10,900px까지 늘어났다.
- 1024px 비교 표에서 AO 칸 배지가 잘렸다.

## 변경

| 위치 | 내용 |
|---|---|
| `detail.js` 재구성 보기 | 높이를 오른쪽 패널 대비 비율 `lv.reconRatio`(기본 0.3, 0.15–0.7)로 저장, CSS 변수 `--recon-ratio`로 적용. 예전 `lv.reconHeight` px 값은 무시 |
| `detail.js` 이미지/검수 분할 | 드래그 폭을 본문 대비 %로 저장. 검수 패널 최소 폭 470px 유지 |
| `app.css` 상단바 | ≤860px에서 줄바꿈, 브랜드 숨김. 390px 목록 상단바는 검색창이 한 줄을 채움 |
| `app.css` 편집 상단 줄 | 스위치 줄바꿈 금지, 항목 단위 줄바꿈, 패널 폭 520px 미만이면 "1.5초 뒤 저장" 숨김(`container-type: inline-size`) |
| `app.css` 재구성 도구 모음 | 줄바꿈 허용 |
| `app.css` 세로 쌓기 | `.detail-right` 높이 85vh, 탭 내용은 패널 안에서 스크롤 |
| `app.css` 비교 표 | `.cmp-cell` 줄바꿈 허용. 칸이 좁으면 배지가 값 아래로 내려간다 |

## 확인

5개 창 크기에서 상세 편집·비교, 목록, 업로드 화면 모두 `scrollWidth == clientWidth`, pageerror 0건. 1600×900→1100×700으로 줄여도 재구성 비율 0.3, 이미지 폭 비율이 유지됐다.

## 한계

- 860px 이하는 세로로 쌓이며 상세 화면은 안쪽 스크롤을 쓴다.
- 문서 사이드바 폭은 px(180–360)로 둔다.
