## 확인한 원인과 수정

- 대상 `20261002-2241-5bf0`: 활성 문서 200건, 비교 시트 49,144개 데이터 행. 기존 엑셀 생성 cProfile 측정 300.795초 중 288.183초가 49,345번의 `Worksheet.max_row` 호출에 쓰였다. 호출마다 셀 전체를 탐색해 누적 행 수에 따라 작업량이 제곱으로 증가했다. 비교·표의 행 번호를 누적하고 표 헤더 셀은 직접 접근한다. 프로파일링 없는 최종 수정본은 약 5.035초, 2,597,017바이트를 생성했다. 서로 다른 측정 방식이므로 정확한 배속 비교로 해석하지 않는다.
- OCR 값뿐 아니라 ID·키·헤더의 제어문자도 정리하고 문자열 셀을 명시적으로 텍스트로 기록한다. `=1+1` 같은 원문이 Excel 수식으로 실행되지 않는다.
- Golden 자동 저장 요청을 순서대로 처리하고 저장한 편집 버전과 현재 버전을 비교한다. 응답 대기 중 추가한 변경이 저장 완료로 표시되지 않는다. 화면 해제 후 콜백·자동 저장 재예약을 차단한다. 삭제는 진행 중 저장 뒤에 실행하고 예약된 자동 저장을 취소하여 삭제한 Golden이 다시 생성되지 않게 한다. 상세 Excel과 ZIP에 동일한 미저장 변경 방지 조건을 적용한다.
- Golden 생성·저장·삭제는 기존 번들·문서 존재를 확인한다. 알 수 없는 경로에 파일을 만들어 번들을 생성하던 부작용을 막는다. 단일 문서 ZIP도 없는 문서에는 404를 반환한다.
- 필드·그룹·표·행·키·dtype의 중첩 형태를 검증한다. 잘못된 저장은 422이고 기존 Golden 파일은 보존한다. 업로드된 잘못된 canonical JSON과 AO 변환 실패는 문서 오류로 보고한다. 빈 AO documents에서 문서 종류를 지정해 생성하는 경우도 처리한다.
- ZIP 압축 파일 크기뿐 아니라 압축 해제될 항목 크기 합도 같은 업로드 제한으로 검사한다. 번들을 만들기 전에 413으로 거절한다.
- async 변경 라우트의 파일 읽기·쓰기·비교·번들 집계를 스레드에서 실행해 이벤트 루프가 막히지 않게 한다.
- 목록의 데이터 누락 필터를 백엔드 집계와 맞춘다. 선택 사항인 전처리 이미지가 없다는 이유로 누락 목록에만 포함되던 불일치를 수정한다.

## 전체 번들 탐색

홈에서 `#/bundles`로 이동하여 전체 번들을 이름·ID로 검색하고 정렬하며 각 번들로 이동한다. 업로드 화면의 최근 번들 영역과 별도로 전체 탐색 화면을 제공한다.

## 검증

- 백엔드 전체 회귀 테스트: 80개 통과(엑셀 출력·상태 색상·표 헤더, 수식 문자열·제어문자, 없는 문서 내보내기, ZIP 확장 크기, Golden 존재·중첩 형태·파일 보존·빈 AO 목록 포함).
- 실제 대상 번들의 수정 전후 집계 일치, 오류 0건. 엑셀 시트 행 수: 요약 202, 필드 4,801, 표 5,942, 비교 49,145.
- Playwright 자동 저장 검사 통과: 저장 대기 중 추가 편집, 연속 저장·실패 후 복구, 화면 종료 후 콜백 방지, 저장 뒤 삭제 순서 및 재생성 방지. 재현 스크립트: `scripts/verify_editor_save.py`(별도 Playwright와 Chromium 필요).
- 전체 번들 브라우저 검사 통과: 62개 가상 번들의 검색·정렬·50/12건 페이지 이동·키보드 이동·390px 모바일 너비·에러 재시도·빈 목록. 홈은 최근 5개를 표시하고 전체 목록 링크를 제공한다.
- dev 병합 후 로컬 8765 서버를 재시작했다. 실제 활성 200건 다운로드는 HTTP 200, 약 4.173초, 2,597,018바이트로 완료됐다. 서버 health 정상 및 전체 번들 API 응답을 확인했다.

## 추가 검토 항목과 기능 제안

- 내보내기 준비 상태·소요 시간·실패 메시지·중복 실행 방지, 대용량 작업의 진행률과 취소 기능.
- 현재 검색·유형 필터 또는 선택 문서만 내보내기.
- Golden 변경 이력·복원과 여러 탭 또는 사용자 간 편집 충돌 감지. 현재 요청 순서 보장은 한 편집기 내부에 적용된다.
- Content-Length 없는 multipart 요청은 파싱 중 임시 디스크에 먼저 저장될 수 있다. 이번 제한 보완은 압축 해제 크기와 업로드 후 파일 합계를 대상으로 하며, 수신 중 바이트 제한은 별도 검증이 필요하다.
- 코드 검토와 재현한 범위의 수정이며 모든 잠재 오류의 부재를 보장하지 않는다.
