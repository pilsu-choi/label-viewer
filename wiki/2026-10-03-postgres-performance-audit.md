## 원인과 성능 측정

200건 Excel 내보내기는 파일 파싱·비교·Excel 작성 시간이 지배한다. 초기 PostgreSQL 구현은 짧은 메타데이터 호출마다 연결을 새로 만들고, 문서마다 번들 전체 상태를 다시 읽으며, 매 문서 진행률을 잠금·조회·갱신했다. DB 도입만으로 파일 처리 병목이 사라지지 않고 연결·왕복 비용이 더해졌다.

문제 유형은 반복 작업 안에서 불변 상태를 재조회하고 자원 생성·상태 기록을 반복하는 구조다. 워커별 psycopg 연결 풀, 중첩 호출의 연결 공유, Excel당 단일 번들 상태 조회, 사용하지 않는 이미지 페이지 수 조사 생략, 0.5초 간격 진행률 기록으로 해당 비용을 제거했다. 준비·마무리 단계는 즉시 기록하고 취소와 heartbeat는 별도로 확인한다.

같은 로컬 PostgreSQL·저장소, 동일 번들 활성 문서 200건, 두 앱 워커에서 요청부터 ready 확인·파일 다운로드까지 3회 측정했다. 개선판은 별도 포트 18965에서 실행했다. 회귀 테스트와 동시에 실행한 초기 개선판 측정(4.974/7.945/5.019초)은 부하 간섭이 있어 아래 비교에는 사용하지 않았다. 테스트가 끝난 뒤 다시 측정했다.

| 버전 | 1회 | 2회 | 3회 | 중앙값 |
|---|---:|---:|---:|---:|
| 이전 PostgreSQL 구현 | 10.001초 | 10.537초 | 10.240초 | 10.240초 |
| 개선판 | 5.055초 | 4.918초 | 4.831초 | 4.918초 |

중앙값 기준 약 52.0% 감소했다. 이전 대화의 파일 모드 4.9초는 동일 조건 반복 측정이 아니므로 DB가 파일 모드보다 빠르다는 근거로 사용하지 않는다. XLSX ZIP 무결성을 검사하고 시간 메타데이터를 제외한 모든 `xl/` 항목 SHA-256을 비교했다. 6회 모두 `6fd2cd499cd428224508caa9d4cd038f38f2ad264af5999d0d8a77a17800535b`로 내용이 같았다.

## 이미지 회전 보기

상세 이미지 도구 모음에 왼쪽/오른쪽 90도 회전, 각도 표시, 회전 초기화를 추가했다. 이미지와 bbox를 함께 회전하고 fit-width/fit-page, bbox focus, 미니맵 viewport·클릭 팬에도 같은 좌표 변환을 적용한다. 회전 시 페이지 맞춤으로 돌아간다.

각도는 상세 화면 세션 안에서 원본/전처리·TIFF 페이지별로 기억한다. 새로운 이미지의 첫 진입, 다른 문서, 새로고침은 0도다. 원본 이미지와 OCR/Golden 좌표는 그대로다.

Chromium 비대칭 이미지 회귀는 0/90/180/270도 캔버스·bbox·미니맵 bounds, bbox focus, fit-width, minimap pan, resize, reset, 늦은 이미지 load, 실제 상세 toolbar와 페이지/이미지 전환을 검사한다.

## 남는 한계

DB 메타데이터와 파일 현재본은 서로 다른 저장 장치다. 정상 예외는 보상 복원하지만 프로세스 강제 종료·전원 장애가 두 저장 사이에서 발생하면 완전한 원자성을 보장하지 않는다. 앱 중단 후 DB와 파일을 같은 시점으로 백업해야 한다. Golden을 내보내는 동안 다른 문서를 편집하면 각 문서는 잠금으로 안전하게 읽지만 전체 문서가 하나의 시점인 것은 아니다. 이미 JSON number로 표현된 큰 수는 브라우저 JSON 파싱에서 정밀도가 손실될 수 있으므로 식별자·고정밀 값은 문자열로 제공해야 한다. 롤백 preflight 이후 디스크 오류까지 다중 파일 원자적으로 되돌리지는 않는다. `--dry-run`은 파일 개수 보고이며 내용 무결성 검증 완료를 의미하지 않는다.
