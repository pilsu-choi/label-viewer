## 원인 (r8, 서버 로그 03:15~03:33 UTC 요청 30건, 합계 3,969초)

| 단계 | 중앙값 | p90 | 최대 | 비중 |
|---|---|---|---|---|
| 대기 + OCR(PaddleOCR 레이아웃 GPU, 동시 2에서 포화) | 28초 | 77초 | 88초 | 27% |
| 표 교정(OpenRouter VLM, 표마다 순차, 칸 수 비례 — 2,364칸 224초) | 23초 | 96초 | 224초 | 29% |
| 추출 | 6초 | 60초 | 122초 | 14% |
| 재처리 루프(크롭 재OCR·VLM, 상한 60초를 진행 중 호출이 넘김) | 43초 | 60초 | 98초 | 31% |

- 응답 표 행 수와 요청 시간은 상관 없음(-0.01) — 표 디코드 길이가 주원인이 아니다.
- 필드·표 요청이 같은 페이지를 각각 처음부터 처리(OCR·표 교정 2회).
- Docraft에 동시 처리 제한이 없고, 하네스는 작업 4개 × 요청 2개를 보낸다.
- 408이 180초가 아닌 184~278초에 난 이유: OpenRouter가 keep-alive 공백을 보내 httpx timeout(바이트 간격)이 끊기지 않았다.

## 대응 (Docraft dev `298570b`, 설정으로 끌 수 있음)

| 대응 | 설정(기본) |
|---|---|
| 같은 페이지 OCR·표 교정 결과 공유(동시 요청은 먼저 온 계산을 기다림) | `READ_CACHE_SIZE=8`, `READ_CACHE_TTL_S=180` |
| 표 교정 병렬, 큰 표는 행 묶음 분할 호출 | `REFINE_CONCURRENCY=4`, `REFINE_MAX_CELLS=300` |
| PaddleOCR 레이아웃 동시성 세마포어(대기 중 시한 초과 → 즉시 408) | `OCR_CONCURRENCY=2` |
| 재처리 루프: 남은 시간이 적으면 원격 단계 생략 | `REPROCESS_MIN_STAGE_MS=30000` |
| 모델 호출을 벽시계 시한으로 끊음(keep-alive 대응) | — |
| `read finished` 로그에 단계별 시간 | — |

권장: Docraft `.env.aws`에 `READ_MAX_MS=280000`(하네스 `DOCRAFT_TIMEOUT=300`보다 짧게). 테스트 660 통과. 배포 담당 6c에 반영 요청 — 효과 수치는 배포 후 서버 로그로 다시 집계한다.

## 배포 결과 (AWS 1002i, `e2e/out/golden1002-aws-r9/`, Docraft 298570b + `READ_MAX_MS=280000`)

| 지표 | r8 | r9 |
|---|---|---|
| Docraft 실패(408 등) | 3 | **0** |
| 요청 소요 중앙값 / p90 / 최대 | 129 / 185 / 278초 | **86 / 144 / 152초** |
| 정확도(5491 정답지) | 99.40% | 99.40% (재처리 채택 회귀 없음) |

- 서버 로그 단계별(51줄, 새 로그 형식): OCR 중앙값 15초·OCR 대기 0초(p90 6초)·표 교정 8초(p90 56초)·추출 5초·재처리 21초(r8 43초).
- 45314 선별급여·끝수처리 행 복원(9칸 개선). 악화 1칸(400b 납부할금액 0→11000)은 PAYABLE 규칙 의미 문제 → harness dev `cd1461a`(규칙셋 2026.09.20, 전액 수납이면 납부할금액 빈칸 인정)로 수정, 6c에 반영 요청.
- 결과 공유 캐시: 로그상 17쌍 중 6쌍이 `cache_hit=False`였으나, 17쌍 모두 표 교정을 한쪽만 해 **실제 공유는 전부 동작**했다. 재처리 크롭 재OCR이 같은 공유 경로를 지나며 `cache_hit`를 덮어쓴 기록 오류 → Docraft dev `49b0baa`(첫 호출 값만 남김). `ocr_ms`에는 재처리 크롭 재OCR 시간도 들어간다.

## 남은 위험

- 캐시·세마포어는 프로세스 안(uvicorn 단일 프로세스라 현재는 유효).
- 표 교정 분할은 호출마다 표 전체 이미지를 보내 입력 토큰이 는다.
- `REPROCESS_MIN_STAGE_MS`로 재처리 채택률이 떨어지는지 다음 측정에서 확인.
- 하네스 쪽 전체 워커 Docraft 동시 호출 상한은 미구현(측정 후 결정).
