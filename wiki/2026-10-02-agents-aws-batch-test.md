## 배경

harness·Docraft의 이슈 대응·신규 기능 브랜치마다 따로 AWS 테스트를 돌려서 외부 호출 건수가 많아졌다.
처음에는 고정 배포 주기와 호출 총량을 검토했지만, 10/6 단위 테스트 일정처럼 촉박할 때 맞지 않아 **그 시점에 떠 있는 세션들의 작업을 취합하는 방식**으로 정했다.

## 규칙 요지

- AWS 배포와 테스트 호출은 배포 담당 세션 하나만 한다. 담당: `mirae-assets-9f`(2026-10-02 09:31 배포까지) → `mirae-assets-6c`(이후, 사용자 지시).
- 일반 세션은 dev에 push한 뒤 배포 담당에게 요청하고, 공유된 결과로 판단한다. 같은 배포본을 다시 호출하지 않는다.
- 배포 담당은 요청이 오면 떠 있는 세션 전체에 안내하고 30분간 모은 뒤 dev 기준으로 한 번 배포한다.
- 테스트는 요청 세션들이 보낸 문서를 합쳐 한 번만 호출한다. 정답지 59건 회귀는 영향 범위가 넓을 때만 넣는다.
- 한 번에 100건을 넘으면 사용자에게 알리고 진행한다(차단하지 않음).

## 사용자가 배포를 지시했을 때 (GO/HOLD 확인)

2026-10-02 첫 실행에서 쓴 절차를 규칙으로 남겼다. 지시를 받은 세션이 조율하고, 배포는 배포 담당이 한다.

1. 조율 세션이 나머지 세션 전체에 배포 대상 커밋을 적어 GO/HOLD를 묻는다.
2. HOLD가 있으면 이유와 예상 시각을 배포 담당과 사용자에게 알리고 그 뒤로 미룬다.
3. 전원 GO면 세션들이 요청한 커밋 변경과 확인 문서를 합쳐 배포 담당에게 넘긴다.
4. 배포 담당이 한 번 배포하고 테스트를 한 번 돌린다.
5. 배포 담당이 결과 경로·배포 커밋·호출 건수를 모든 세션에 보내고 각자 분석을 요청한다.

첫 실행(09:27~): f3·harness-v2-37·6f·harness-v2-f1 전원 GO. f1 요청으로 harness 배포 커밋을 `29c7e07`→`6d30de5`(규칙셋 2026.09.15)로 바꿔 Docraft `88087b5`와 함께 9f에 넘겼다.
